English guide →

وضعیت: در حال ساخت. هر دو ماژول ساخته و تست می‌شوند؛ هنوز چیزی روی Maven Central منتشر نشده. اینترستیشیال، پاداشی و پوسته‌های یونیتی/فلاتر بعداً می‌آیند.

kotlin
// یک‌بار، در Application.onCreate
Sanbuk.init(context, mediaCode = "YOUR-MEDIA-CODE")

ما بکشیم — ویویی که خودش می‌گیرد، می‌کشد، نمایش را می‌شمارد و کلیک را مسیریابی می‌کند:

kotlin
SanbukAdView(context).apply { load(placementCode = "HOME-TOP") }

خودت بکش — همان تبلیغ به‌صورت داده، با استایل UI خودت:

kotlin
val ad = Sanbuk.loadAd(placementCode = "HOME-TOP")   // تیتر، تصویر، دکمه، رنگ برند
// ...با ویوهای خودت رندرش کن...
ad.recordImpression()   // وقتی واقعاً روی صفحه است
ad.click()              // وقتی کاربر رویش زد

تمام‌صفحه — اینترستیشیال بین دو لحظه، یا آگهی پاداشی که کاربر خودش خواسته:

kotlin
SanbukFullscreen.load(context, "LEVEL-END") { ad -> pending = ad }

pending?.show(activity, callbacks = object : SanbukFullscreen.Callbacks {
    override fun onClosed() = startNextLevel()
})

SanbukFullscreen.loadRewarded(context, "EXTRA-LIFE") { ad ->
    ad?.show(activity, callbacks = object : SanbukFullscreen.Callbacks {
        override fun onReward() = grantExtraLife()
    })
}

داده اول: سرور تبلیغ را توصیف می‌کند، اپ تو آن را می‌کشد

سنبوک هرگز نشانه‌گذاری نمی‌فرستد. نه HTML، نه بنر ازپیش‌رندرشده، نه وب‌ویوی پنهان. پاسخ یک توصیف است — تیتر، متن، تصویر، متن دکمه، رنگ برند — و اینکه با آن چه می‌کنی با توست.

این نکتهٔ اصلی این SDK است، نه یک جزئیات فرعی. تبلیغی که با فونت، فاصله و انیمیشن خودِ اپ کشیده شود شبیه بخشی از اپ به نظر می‌رسد، و این چیزی است که هیچ شبکه‌ای که بنر آمادهٔ رندرشده تحویل می‌دهد نمی‌تواند به تو بدهد. SanbukAdView فقط راحتی است روی همان داده، برای اپی که نمی‌خواهد یک بعدازظهر رویش وقت بگذارد — نه مسیر دیگری.

معامله‌اش صادقانه است: وقتی ما می‌کشیم، می‌توانیم اندازه هم بگیریم. زیر SanbukAdView نمایش فقط وقتی گزارش می‌شود که دست‌کم نیمی از تبلیغ یک ثانیهٔ کامل روی صفحه بوده باشد. وقتی خودت می‌کشی، زمان recordImpression() را تو تعیین می‌کنی و ما راهی برای راستی‌آزمایی نداریم — به همین دلیل رسانه‌هایی که این‌طور ادغام می‌شوند برچسب می‌خورند و کمی دقیق‌تر پایش می‌شوند.

فرمت را ناشر انتخاب می‌کند، کد تو فقط «چطور کشیدن» را

banner، native، interstitial و rewarded هنگام ثبت جایگاه در پنل سنبوک انتخاب می‌شوند و پاسخ می‌گوید کدام آمده. گزارش، کمیسیون per-format و شرط سازگاری کریتیو همه به همان مقدار ثبت‌شده تکیه می‌کنند، پس چیزی نیست که کلاینت بتواند اعلامش کند.

دو ماژول، یک پیاده‌سازی

ماژولچه چیزی آنجاستوابسته به اندروید؟
coreقرارداد سیم، صف آفلاین، شمارندهٔ فرکانس، قاعدهٔ شمارش نمایش، هویت نصبنه — Kotlin/JVM خالص
sdkویوها، Custom Tabs، ذخیره‌سازی، چرخهٔ عمربله

هر چیزی که تصمیم می‌گیرد در core است. قاعده‌ای که داخل پوسته بنشیند باید برای هر پوسته دوباره نوشته شود — یونیتی، فلاتر، React Native — و پوسته‌ها با سرعت‌های متفاوت آپدیت می‌شوند، پس نسخه‌ها از هم دور می‌افتند. یک پیاده‌سازی، چند پل نازک.

سود جانبی‌اش: core روی هر JDK ای کامپایل و تست می‌شود، بدون اینکه اصلاً Android SDK در کار باشد.

یک آرتیفکت خودبسنده

فایل AAR کلاس‌های core را در خودش دارد، نه به‌صورت وابستگی به ماژول دوم. وابستگی گرِیدل برای بیلدی که به Maven Central می‌رسد خوب است؛ خیلی‌ها نمی‌رسند — مخصوصاً پلاگین یونیتی که به‌شکل یک .aar دراپ‌این و بدون هیچ مرحلهٔ resolve توزیع می‌شود — و آرتیفکتی که در اولین اجرا NoClassDefFoundError بدهد از نبودنش بدتر است.

core یک ماژول واقعی می‌ماند تا همان سورس‌ها روی یک JVM ساده هم کامپایل و یونیت‌تست شوند.

پنج قاعده‌ای که این SDK رویشان ساخته شده

۱. هرگز نکش، هرگز نمیر. هیچ استثنایی از این SDK نباید به اپ میزبان برسد. بدترین حالت مجاز یک جعبهٔ خالی است. کرشی که ما ساخته باشیم یعنی ریویو یک‌ستاره برای ناشر و حذف SDK.

۲. هیچ I/O روی ترد اصلی. ANR در کلد استارت سریع‌ترین راه حذف‌شدن است.

۳. تصمیم‌ها سمت سرور می‌مانند. ماچینگ، pacing، فرکانس‌کپ، دورهٔ آزمایشی، بودجه — همه سمت سرورند و همان‌جا می‌مانند. این SDK می‌پرسد، می‌کشد، و گزارش می‌دهد. نسخه‌ای که روی گوشی‌ها رفته ماه‌ها منجمد است؛ هر قاعده‌ای که اینجا سفت شود سال‌ها با ما می‌ماند.

۴. کلیک مرورگر واقعی را باز می‌کند. Custom Tabs، هرگز WebView درون‌اپ. سبد کوکی جدا انتساب first-party را می‌شکند، و در یک شبکهٔ CPA انتساب شکسته یعنی ناشر کار کرده و پولی نمی‌گیرد.

۵. بدون شناسهٔ تبلیغاتی. نه GAID، نه IDFA. فقط یک install_id تصادفی و ریست‌شدنی، برای فرکانس‌کپ و به‌عنوان کلید محدودیت نرخ که پشت CGNAT اپراتورها هنوز معنا دارد.

ساخت

bash
./gradlew build

core فقط به یک JDK نیاز دارد و به‌تنهایی هم تست می‌شود (./gradlew :core:test). لایهٔ اندرویدی به Android SDK نیاز دارد؛ مسیرش را در local.properties بگذار:

sdk.dir=/path/to/Android/sdk
